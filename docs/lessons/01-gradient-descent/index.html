Linear Regression & Gradient Descent

How does a machine "learn"? It makes a guess, measures how wrong it is, and nudges the guess to be a little less wrong. Repeat.

The one-line idea

Learning = finding the parameters that make the error as small as possible, by repeatedly taking small steps "downhill" on the error.

Why it matters

Almost every model in deep learning — from a straight line to ChatGPT — is trained the same way: define an error (the loss) and reduce it with gradient descent. A neural network just has millions of parameters instead of two. If you understand this lesson, you understand the training loop of all of them.

Prerequisites: none. A rough idea of what a slope is helps.

Intuition

Imagine you are standing on a foggy hill and want to reach the lowest valley. You cannot see far, but you can feel which way the ground tilts under your feet. So you take a step in the downhill direction, feel again, take another step… Eventually you reach the bottom.

  • Your position on the hill = the model's parameters (e.g. slope and intercept of a line).
  • Your height = the loss (how wrong the model is).
  • The tilt under your feet = the gradient.
  • Your step size = the learning rate.

Step 1 · From data to a loss

We have 8 houses. For each we know its size and its price. We want a straight line that predicts price from size. Click through:

  1. The data. Each blue dot is one house: size on the x-axis, price on the y-axis. Bigger houses tend to cost more — there is a trend.
  2. A model = a guess. Our model is a line \(\hat y = w\,x + b\). Here we picked random values w = 0.4, b = 2.2. The orange line is clearly not great.
  3. Measure the errors. For each house, the red dashed line is the gap between the real price \(y\) and the predicted price \(\hat y\). This gap is called the residual.
  4. Square and average → the loss. We square every error (the red boxes) so negatives don't cancel positives and big mistakes count more. The average box area is the Mean Squared Error (MSE). One number that says "how wrong".
  5. A better line has a smaller loss. With w ≈ 1.45, b ≈ 0.55 the boxes almost vanish. Learning means finding these values automatically. That is what gradient descent does.

Step 2 · Walking downhill on the loss

Every choice of \(w\) gives a different loss. If we plot loss against \(w\) we get a bowl-shaped curve. (We keep \(b\) fixed here so the picture is 2-D.)

  1. The loss landscape. The x-axis is the parameter \(w\); the y-axis is the loss for that \(w\). The best \(w\) sits at the bottom of the bowl.
  2. Start anywhere. We don't know where the bottom is. We start at a random \(w\) — the orange ball.
  3. Feel the slope. The red tangent line shows the slope (the gradient) at the ball. It is negative: the curve goes down as \(w\) increases.
  4. Step against the slope. Negative slope → move right. The update is \(w \leftarrow w - \eta \cdot \text{slope}\). The green arrow is that step; \(\eta\) is the learning rate.
  5. Repeat. Each step recomputes the slope. Near the bottom the slope is small, so the steps get smaller automatically — the ball settles at the minimum.

The math (light)

Model — a line with two parameters, slope \(w\) and intercept \(b\):

$$\hat y_i = w\,x_i + b$$

Loss — the mean squared error over all \(n\) data points:

$$L(w,b) = \frac{1}{n}\sum_{i=1}^{n} \big(\hat y_i - y_i\big)^2$$

Gradients — how much the loss changes if we nudge each parameter (using the chain rule):

$$\frac{\partial L}{\partial w} = \frac{2}{n}\sum_{i=1}^{n} (\hat y_i - y_i)\,x_i \qquad \frac{\partial L}{\partial b} = \frac{2}{n}\sum_{i=1}^{n} (\hat y_i - y_i)$$

Update rule — step against the gradient, scaled by the learning rate \(\eta\):

$$w \leftarrow w - \eta\,\frac{\partial L}{\partial w} \qquad b \leftarrow b - \eta\,\frac{\partial L}{\partial b}$$
Reading the gradient formula: \((\hat y_i - y_i)\) is the error on point \(i\). If we predict too high (positive error), the gradient is positive, so the update lowers \(b\) — exactly what we'd do by hand. For \(w\), each error is weighted by \(x_i\): big houses have more say in the slope.

Tiny code

The whole algorithm in NumPy — about 10 lines. This is the same data as the visuals above.

import numpy as np

x = np.array([0.5, 0.8, 1.0, 1.3, 1.6, 1.9, 2.2, 2.5])   # size (100 m²)
y = np.array([1.4, 1.5, 2.1, 2.3, 3.0, 3.2, 3.9, 4.1])   # price (100k)

w, b = 0.0, 0.5      # initial guess
lr = 0.2             # learning rate (η)

for step in range(300):
    y_hat = w * x + b                     # 1. predict
    err = y_hat - y                       # 2. errors
    loss = np.mean(err ** 2)              # 3. MSE loss
    grad_w = 2 * np.mean(err * x)         # 4. gradients
    grad_b = 2 * np.mean(err)
    w -= lr * grad_w                      # 5. step downhill
    b -= lr * grad_b
    if step % 50 == 0:
        print(f"step {step:3d}  loss {loss:.4f}  w {w:.3f}  b {b:.3f}")

print("learned:", w, b)    # ≈ 1.45, 0.55

The same loop in PyTorch, where gradients are computed automatically (this is what you'll use for real neural networks):

import torch

x = torch.tensor([0.5, 0.8, 1.0, 1.3, 1.6, 1.9, 2.2, 2.5])
y = torch.tensor([1.4, 1.5, 2.1, 2.3, 3.0, 3.2, 3.9, 4.1])
w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.5, requires_grad=True)
opt = torch.optim.SGD([w, b], lr=0.2)

for step in range(300):
    loss = ((w * x + b - y) ** 2).mean()
    opt.zero_grad()      # clear old gradients
    loss.backward()      # compute dL/dw, dL/db automatically
    opt.step()           # w -= lr * w.grad, b -= lr * b.grad

Common mistakes & questions

  • "Why square the errors instead of using absolute value?" Squaring is smooth (easy to differentiate everywhere) and punishes big mistakes more. Absolute error (MAE) is also used — it is more robust to outliers.
  • "Why minus the gradient?" The gradient points in the direction where the loss increases fastest. We want to decrease it, so we go the opposite way.
  • Forgetting to scale features. If \(x\) is in the thousands (e.g. size in m² instead of 100 m²), gradients become huge and the same learning rate explodes. Normalise inputs first.
  • "Does it always find the best answer?" For linear regression yes — the loss is a single bowl (convex). For neural networks the landscape has many valleys, but gradient descent still works remarkably well in practice.
  • Batch vs. stochastic. Here we used all 8 points per step (batch gradient descent). With millions of points we use a small random subset per step — stochastic / mini-batch gradient descent (SGD). Same idea, noisier steps.

Recap

  • A model has parameters (here \(w, b\)); a loss measures how wrong it is (here MSE).
  • The gradient tells us the uphill direction of the loss for each parameter.
  • Gradient descent: repeat \(\theta \leftarrow \theta - \eta \nabla L\) until the loss stops improving.
  • The learning rate \(\eta\) controls step size: too small = slow, too big = diverges.
  • This exact loop (predict → loss → gradients → update) trains every neural network.

Self-check

1. At the current \(w\), the gradient \(\partial L/\partial w = -3\). Should \(w\) go up or down?

Up. \(w \leftarrow w - \eta(-3) = w + 3\eta\). A negative slope means the loss decreases as \(w\) grows.

2. Your loss gets bigger every step and eventually becomes NaN. What is the most likely cause?

The learning rate is too large — each step overshoots the minimum by more than the last one. Lower \(\eta\) (e.g. divide by 10), and check that inputs are normalised.

3. What happens to the step size near the minimum, even with a fixed learning rate?

It shrinks, because the step is \(\eta \times\) gradient and the gradient approaches 0 at the bottom of the bowl.

4. Why can't we just make the learning rate as tiny as possible to be safe?

It would converge, but needs a huge number of steps. Training time matters — you want the largest learning rate that is still stable.

5. In the formula for \(\partial L/\partial w\), why is each error multiplied by \(x_i\)?

Chain rule: \(\hat y_i = w x_i + b\), so \(\partial \hat y_i / \partial w = x_i\). Changing \(w\) moves predictions for large \(x\) more than for small \(x\).
